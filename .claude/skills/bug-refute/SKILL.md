# バグ修正の独立した反証

修正と回帰テスト、触った範囲の検証が揃った後に 1 回行う。
指摘で修正範囲が大きく変わったときだけ再度行い、「指摘なしになるまで」の反復はしない。

## 渡す材料

- Issue の症状と再現手順。完了条件・推測した原因の部分は除く。
- 対象 worktree の絶対パスと、`git diff origin/main...HEAD` の差分。
  未コミットの変更がある場合は `git diff HEAD` と新規ファイルも併せて渡す。

プラン・完了条件・PR 本文・実装者の原因の推測は渡さない。
反証役は自由にコードを読めるが、Issue / PR のコメントを取得しない。

## 独立した担当者への依頼

履歴を継承しない読み取り専用のサブエージェントを 1 つ起動する。
Codex は `spawn_agent` の `fork_turns: "none"` を使い、モデルは環境の既定に従う。
別のエージェント製品でも会話履歴を渡さず、次の依頼と上記の材料だけを渡す。

```text
dropcaster のバグ修正の反証役として、症状・再現手順と差分だけを読み、次を調べてください。
1. 同じ根本原因・同じ前提を持ち、修正が届いていない入口や呼び出し元
2. 変更した関数・状態・既定値を使う別経路への副作用
3. 根本原因を直したか、症状だけを塞いだか
ファイル変更・コミット・GitHub の読み書きはしないでください。
指摘は file:line を根拠にし、種類・指摘・根拠の表と、試した rg 検索式を返してください。
見つからなかった項目はそう書き、調べた範囲を示してください。
```

独立したエージェントが使えない環境では、同じ材料だけを渡す別セッションか人に依頼する。
手配できなければ「未実施」と明記し、バグ修正 PR は Draft で引き継ぐ。
実装者の読み直しを独立した反証として記録しない。

## 指摘への対応

| 対応 | 記載するもの |
| --- | --- |
| 直した | 修正内容と回帰テスト |
| 別 Issue にした | Issue 番号と、根本原因が違う／仕様の選択が必要という理由 |
| 当たらない | 根拠の file:line・既存テストなど |

同じ根本原因の別箇所は同じ PR で直す。差分の外・大きいというだけで別 Issue に送らない。
不採用の指摘も消さない。PR の「反証」に担当者、渡した材料、指摘・根拠・対応、検索式を載せる。
指摘がなければ「指摘なし」と調べた範囲を残す。
