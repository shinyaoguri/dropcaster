# 0015: 会場作成と実機の位置合わせを独立させる

## 状態

採用。#138。0014の立体編集操作と保存形式を継承し、編集する場所を独立画面へ移す。

## 文脈

作品を投影する3Dプレビューに会場作成を同居させると、現場でモデルの寸法・投影条件を合わせる作業と
作品を調整する作業が混ざる。現場調整にはp5.js作品は不要で、実物の辺に重ねる輪郭と位置合わせのパターンが必要。

## 決定

- `/venue` を作品なしで開ける独立画面にする。既存の立体GUIを再利用し、寸法・投影位置・レンズ条件をここで調整する。
- マッピング内の3Dは観察・投影確認・会場ファイル読込に特化する。会場の入口はホームと設定メニューへ置く。
- 実出力は別のcanvasで仮想プロジェクタ視点の輪郭を描き、既存OutputWindowへ等倍のソース領域で渡す。
  観察カメラ・操作ガイド・作品・保存済みの2D変形は含めない。grid/white/blackも同じcanvasから出す。
- canvas backing storeの解像度を基準にし、窓のCSSサイズと分離する。出力開始はボタンのみ。
  終了・画面遷移・WebGL停止で専用streamを停止する。既存WindowControllerのstreamは借用しない。
- `venue-draft` を独立した保存キーにする。名前付き作品一覧からは除外し、既存draft・2D localStorageへは書き込まない。
- 既存会場のコピーは明示操作で読み出す。完成した会場は既存Venue v2ファイルを書き出し、マッピング側で明示的に読み込む。
  Project v3/Venue v2と以前の読込形式を維持する。作品や再生順序は会場の下書きへ保存しない。

## 影響

現場で作成・調整した会場を、作品から独立して配布できる。既存の作品を再生しながら別タブで作業できる。
会場ファイルの読込は会場・投影条件・2D配置を反映するため、必要な既存配置は事前にコピーまたはパッケージで保存する。
調整結果を作品側へ自動同期しない。実機側の解像度・アスペクト比・全画面設定はユーザーが合わせる。
ブラウザ回帰テストで描画ピクセル・別窓・既存stream・保存分離・読込互換を検証する。
