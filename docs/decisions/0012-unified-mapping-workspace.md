# 0012: マッピングの入口を統一し、3Dを右側の任意タブにする

## 状態

採用（2026-11-12 JST）。#132 / #133。[0010](0010-portable-project-and-practice-ui.md) の
UI配置・入口・初期化時期を更新する。Project v2 / Venue v1 の保存契約は変えない。

## 文脈

従来の本番入口はクリック直後に出力窓を開き、3D練習は別の入口を使っていた。
実際には同じソースとマッピングを編集するため、ユーザーは目的に応じた入口を選ぶ必要がない。
また、ソース下部の3Dビューは編集領域を狭める。ユーザーの提案に従い、既存タブへ統合する。

## 決定

- 個別作品・スライドショーとも既存のマッピングボタンで編集を開く。初期タブはマッピング。
  出力追加も含めて自動的に別窓を開かず、出力一覧の「開く」だけで実出力を開始する。
- 右側に「マッピング」「出力レイアウト」「3Dプレビュー」を並べる。ソースは独立した列を使う。
  狭い画面ではツールを左、ソースとタブを右の上下に配置する。
- MappingWorkspace が編集の stream consumer を所有する。実出力とは独立し、最後の窓を閉じても
  編集を維持する。編集を閉じても実出力とスライドショーの送りを継続する。最後の消費者終了で停止する。
- 3Dタブ、会場・3D設定・プロジェクトの明示操作、保存プロジェクトの再開でのみ PracticePanel を
  読み込む。通常2Dの開始時には Three.js / WebGL を必要としない。パネル初期化は重複させず、
  遅延完了は編集世代とパネル所有者を確認する。読み込み中にタブを変えても表示を戻さない。
- 3Dが非表示の間は描画ループを止め、視点・設定を保持する。ソースと実出力は止めない。
  固定背景は編集用に保ち、実出力へ混入させない。3D失敗時は2Dへ戻し、再試行を提供する。
- サンプル入口を `/mapping` にし、従来の `/practice` ブックマークも同じ画面へ解決する。

## 影響

練習・本番のモード切替がなくなる。投影を始める操作と編集を開く操作が明確になる。
通常2Dの初期化コストを保ち、3Dタブを使った後も非表示中のGPU描画を抑える。
3Dは引き続き選択した1台分。複数仮想プロジェクタは #129 で扱う。

両viewer経路で、出力窓・編集画面の独立した寿命、3Dなしの編集、タブ復帰後の四隅編集、
キーボード操作、会場・保存プロジェクトの互換性をブラウザ回帰テストへ含める。
