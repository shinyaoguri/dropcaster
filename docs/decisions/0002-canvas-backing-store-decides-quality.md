# 0002: 投影出力の画質は canvas バッキングストア解像度だけで決める

- **状態**: 採用（2026-08-05 に記録。判断自体は初期実装から一貫）
- **文脈**: 「4K プロジェクタに出すには 4K ディスプレイで作業しないといけないのか」「出力ウィンドウを最大化しないと画質が落ちるのか」という問いが繰り返し出る。実際のパイプラインは `canvas` → `captureStream()` → `<video>` → `matrix3d` ワープであり、ストリームが運ぶフレームの解像度は `canvas.width × canvas.height`（バッキングストア）で決まる。表示ウィンドウの CSS サイズやディスプレイのピクセル比は、そのフレームをどう表示するかに関わるだけで、フレーム自体の情報量には影響しない。
- **決定**: 出力画質はスケッチ側の canvas バッキングストア解像度だけで決まる設計を維持し、**表示ウィンドウ側の解像度に依存させない**。スケッチ作者には「固定の高解像度で canvas を作る」ことを推奨事項として README に書く（p5.js なら `pixelDensity(1)` + `createCanvas(3840, 2160)`。`windowWidth` / `windowHeight` 任せにしない）。
- **影響**:
  - 2K のディスプレイで作業して 4K プロジェクタへ 4K で出す、が成立する。逆に、ウィンドウサイズに応じて解像度を上げる/下げるような最適化は**入れてはいけない**（作業環境によって出力が変わる設計になってしまう）
  - 解像度を上げるほど毎フレームの GPU 負荷（fill rate / VRAM）が増えるため、ライブなマッピングを複数重ねる場合の解像度選択は利用者の判断に委ねる
  - 関連: [README「プロジェクションマッピングで使うスケッチの推奨設定」](../../README.md)、[CLAUDE.md](../../CLAUDE.md)「壊してはいけない前提」
