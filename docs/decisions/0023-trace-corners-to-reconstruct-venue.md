# 0023: 壁に映した十字で実物の角を手でなぞり、会場とプロジェクタ条件を逆算する

## 状態

採用（2026-11-16）。#242 / #243 / #245。[0011](0011-measured-venue-authoring.md) の「測って組む」経路と
[0013](0013-simple-venue-and-projector-guides.md) の「頂点編集は範囲外」の前提を更新する。
[0003](0003-manual-corner-pin-over-camera-calibration.md) で退けたカメラ校正を復活させるものではない。

## 文脈

会場の 3D 空間を作るには、メジャーで会場を測り、壁・床・箱を組み、仮想プロジェクタを動かして壁の上で輪郭を重ねる。
測る・組む・合わせるのそれぞれに手間がかかる。プロジェクタは逆向きのカメラなので、壁の上で指した実物の角は
プロジェクタ画素での像そのものになる。「この面は長方形」「この 3 本の辺は直交する」という知識を足せば、
立体とプロジェクタの両方を逆算できる。#243 / #244 で推定器 (`venueReconstruct.ts`) を作り、
部屋規模の構造と投射比があれば画角の誤差は約 1°、8 m の部屋で頂点の誤差は中央値 15 cm に収まることを合成会場で測った。

推定器はプロジェクタ座標 (プロジェクタが原点・単位回転) で解くので、床の高さも部屋の向きも決まっていない。
会場画面が扱う世界座標の部材とプロジェクタに移す規則が要る (#245)。

## 決定

- **なぞる方式を採る**: 出力窓からプロジェクタで十字を映し、利用者が実物の角へ運んでクリックする。
  人の目がセンサーで、カメラ・グレイコード・密な対応・メッシュ warp は使わない。出力段は CSS `matrix3d` のまま
  ([0002](0002-canvas-backing-store-decides-quality.md))。0003 が退けた「カメラ校正パイプライン」とは、
  入力 (人のクリック数十点 対 カメラの密な対応) も出力 (直方体の部材とプロジェクタ条件 対 メッシュ) も別物。
- **未知数は「プロジェクタ＋頂点」の 1 つの推定器**: 測った頂点を固定値にすれば、同じ推定器でプロジェクタ条件だけを合わせる (#158)。
- **保存するのは従来どおりの部材とプロジェクタ**: 頂点は推定の内部量で、結果は既存の壁・床・箱 (直方体) と `Projector`
  (`verticalFovDegrees` / `aspect` / `lensShift`) に移す。会場ファイル (Venue package v2) と Project v3 の形式は変えない。
  0013 の「頂点単位の編集はしない」は保たれる。
- **対応点 (なぞった角) は会場の下書きにだけ保存し、配布する会場ファイルには含めない** (2026-11-16 合意、#242)。
  なぞった長方形をマッピングの面 (`MappingEntry` の quad) へ流し込むのは見送る ([0015](0015-standalone-venue-calibration.md) の境界をまたぐため)。
- **世界座標の決め方** (`reconstructionToVenue.ts`):
  - 長方形と直交する角が頂点を共有するものを 1 つの部品にまとめる。凹の角 (部屋の隅) を含めば部屋、凸の角か向きの違う長方形を
    含めば箱、同じ平面の長方形だけなら板。決まらない頂点を含む部品は作らず、理由を返す。
  - 上 (+Y) は、部屋の隅の辺 (部屋が無ければ箱・板の辺と法線) のうち出力画像の上に最も近い向き。天吊りでも
    プロジェクタ側で像を正立させる前提なので、画像の上は物理の上になる。
  - 客席 (+Z) は、水平な辺 (と、それを上の軸回りに 90° 回した向き) のうち、プロジェクタへ向かう水平方向に最も近い向き。
    部屋なら奥の壁が −Z 側になる。隅を斜めに狙う配置ではどちらの壁が「奥」になるかは任意。
  - 床 (Y=0) は決まった頂点の最も低いもの。部屋の隅があれば隅、箱だけなら箱の底、長方形だけなら下辺が床に載る。
    天井の隅 (縦の辺が下へ伸びる隅) だけをなぞった構成は、床の高さが決まらないので扱わない。
  - 原点 X/Z は部屋の左右・前後の中央 (`docs/venue-authoring.md` の基準)。部屋が無ければ頂点の外接矩形の中央。
  - 部屋は既存のひな形 (`roomScene`) で作り、壁厚 15 cm・床厚 10 cm を内寸の外側に置く。左右の壁はその側の隅を
    なぞったときだけ作る。なぞっていない方向 (高さ・片側の幅・奥行き) は、プロジェクタの光が届く範囲 (画像の 4 隅の光線と
    奥の壁の交点、奥行きはプロジェクタの位置) まで延ばす。なぞった点の広がりだけでは、3D 練習で光が壁の外へ抜けるため。
  - 箱は水平な辺の向きで外接直方体を取り、底を床まで延ばす (床に置いた箱を想定。台の上の箱・吊った物は扱わない)。
  - 板は長方形の向きの薄い壁 (厚さ 15 cm) で、厚みを面の奥に置く。
  - 縮尺 (`length`) が無ければ、推定の仮の単位のまま同じ規則で出し、「縮尺未設定」を結果に残す。
    会場とプロジェクタを同じ比率で拡大・縮小しても投影出力と 3D 練習の見た目は変わらないので、そのまま使える。

## 影響

現場ではメジャーで測らずに会場とプロジェクタ条件を作れるようになる。数値欄とハンドルでの編集は、仕上げと、
現場にいないとき (図面から作る・配布用に作る) のために残す。利用者向けの記述 (`docs/venue-authoring.md` の
「写真から実寸を推定する機能ではない」など) は、なぞる UI を出す #246 で改める。

扱わないもの: レンズ歪み、長方形でない面と曲面、複数プロジェクタの同時合わせ (#129)、カメラによる自動化 (0003)、
プロジェクタ本体の台形補正が入ったままの合わせ。光が当たっていない角は指せない。
変換の正しさは合成会場の単体テスト (`tests/venue-reconstruct-world.test.js`) で、実機での照合は #242 の子タスクで確かめる。
