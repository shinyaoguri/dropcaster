# 0008: 出力の削除は追加の逆操作として仮想キャンバスを詰め直し、取り残しを残った出力へ寄せる

- **状態**: 採用（2026-11-10）
- **文脈**: 仮想キャンバスは原点 (0,0) から全出力を包む大きさで、`recomputeCanvasBounds`（`src/viewer/utils/mappingTransform.ts`）が `max(position + size)` から求めている。出力の追加 (`withAddedOutput`) は新しい出力を右端に置くので、キャンバスは 1 台ぶん広がる。ところが削除 (`withRemovedOutput`) は出力を配列から抜いて再計算するだけだった。そのため右端以外の出力を消すと、原点との間に消した出力ぶんの空きが残る。マッピングタブ・出力レイアウトタブでは「増やすと広がるのに、減らしても縮まない」状態に見えた（[#99](https://github.com/shinyaoguri/dropcaster/issues/99)）。
- **決定**: 出力の削除を追加の逆操作にする。
  - 削除した出力が占めていた x / y の帯のうち、残りの出力に覆われていない部分を潰す。横並びなら x だけ、縦積みなら y だけが詰まる
  - 出力と mapping / mask は一緒に平行移動する。item は AABB の重なり面積がいちばん大きい残り出力（アンカー）と同じだけ動かす。各出力から見た item の位置が変わらないので、**削除しても残った出力の投影結果は変わらない**
  - 削除した出力の上にあって、残りのどの出力にも乗らなくなる item（取り残し）は、削除した出力の中での相対位置を保ったまま残りの先頭の出力へ移す。キャンバスの外へ出て触れなくなるのを防ぐためで、移った item はその出力に映り始める。辺が接しているだけの出力は「乗っている」とみなさない
  - 削除前からどの出力にも乗っていなかった item は寄せない（自分の左上の位置で詰めた分だけ動く）
- **影響**:
  - 詰めるのは削除した出力の帯だけ。それ以外の出力どうしの隙間（物理的に離れたプロジェクタを模して空けたもの）は残す。出力を重ねて投影している構成では、重なっていた部分は詰めない
  - 削除した出力を挟んで左右の残り出力にまたがる item は、アンカー側に合わせて動くので、反対側の出力での映り方が変わる。稀な構成として割り切る
  - キャンバス（`MappingsState.canvas`）は出力だけを包む。quad は含めない。出力を動かす経路（`withOutputLayoutSet`、出力レイアウトのドラッグ）はこれまでどおり原点を動かさない
  - 断念した代替: (1) キャンバスに原点オフセットを持たせる。保存形式 (version 2) と読み込み互換の対応が要るうえ、中間の出力を消したときの空きは残る。(2) 取り残しを寄せずにキャンバスの外へ出す。投影結果は一切変わらないが、外へ出た item はプレビューで掴めなくなる。(3) キャンバスに quad も含める。取り残しがある限り空きが縮まず、#99 が直らない
