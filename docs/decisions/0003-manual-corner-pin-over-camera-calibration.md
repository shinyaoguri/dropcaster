# 0003: 投影面の対応付けは手動コーナーピンを維持し、カメラ校正は採らない

- **状態**: 却下（2026-07-18）— 将来同じ検討を繰り返さないための記録。再挑戦するときはまずここを読む
- **文脈**: 現行の投影面合わせは CSS `matrix3d` による手動コーナーピン（四隅をドラッグ）で、複雑な面や多面投影では合わせ込みに手間がかかる。これを自動化する構想として、Web カメラ + グレイコード構造化光で「画面ピクセル ↔ 物理投影面」を校正し、出力段を CSS `matrix3d` から WebGL mesh warp に作り替えて、投影面の写真空間でオフライン制作できるようにする案を検討した。
- **決定**: 採らない。PoC まで実施し、WebGL mesh warp の**性能自体は成立を確認**した（実測 2026-06-16: 4K ソース 1 枚 = 120fps、3 枚 = 約 20fps）。しかし校正パイプライン（グレイコード投影 → 撮影 → 密対応 → メッシュ生成）の実装難度が高く、得られる利便性に見合わないと判断した。現行の手動コーナーピン（CSS `matrix3d`）を維持する。
- **影響**:
  - 関連ブランチ `feat/projection-calibration` は削除済み。最終コミットは `62d3de1` で、PoC 2 本（`poc/webgl-mesh-warp/`・`poc/graycode-calibration/`）と `src/viewer/calibration/` を含む。再挑戦するならここから復元できる
  - WebGL mesh warp 単体（校正なし・手動メッシュ編集）は性能的に成立するので、この却下は「カメラ校正パイプライン」に対するものであって mesh warp 全般を否定するものではない
  - 出力段が CSS `matrix3d` のままである前提は [0002](0002-canvas-backing-store-decides-quality.md) の画質設計とも噛み合っている
