# 0021: マッピング画面の左端にアクティビティバーを置き、ツール列をパネルで切り替える

## 状態

採用（2026-11-16）。#215。[0013](0013-simple-venue-and-projector-guides.md) の「設定・共有」メニューと、
[0015](0015-standalone-venue-calibration.md) の「会場の入口は設定メニュー」を置き換える。
3D を明示操作でだけ読み込む [0012](0012-unified-mapping-workspace.md) の原則はそのまま守る。

## 文脈

ツール列には出力・マッピング・出力設定・ソース設定・テストパターン・開発モード・マッピング設定・設定の入出力の
8 セクションがあり、3D 設定とプロジェクト保存も末尾に足されていた。目的の項目までスクロールが要った。
編集履歴（↶ / ↷）は 3 カラムの上の全幅の細いバーに載っており、1 行ぶん縦を削っていた。
3D 設定・会場の作成・保存は「設定・共有」メニューの奥にあり、どこにあるかが見えなかった。

## 決定

- VSCode と同じく、画面の左端に縦のアクティビティバーを置く。上から「マッピング」「出力」「確認」「3D」「プロジェクト」の
  5 パネルを切り替える。既定は「マッピング」。
  - 一覧と選択中の詳細は、一覧で選んですぐ数値を見るので同じパネルに置く。マッピングはマッピング一覧・ソース範囲・四隅、
    出力は出力ウィンドウ一覧・出力の位置とサイズ。
  - 当初は出力とマッピングを 1 パネル（「出力とマッピング」）にまとめていたが、5 セクションが縦に積まれて
    スクロールが残ったため 2 パネルに分けた（#228）。最も長く触るマッピングを先頭・既定にする。
  - 確認はテストパターンと開発モード。3D はプレビュー設定と会場ファイルの読込。プロジェクトは保存・読込と設定の入出力。
- 選択中のアイコンをもう一度押すとツール列を畳み、ソースとマッピングに幅を譲る。どれかのアイコンで開き、
  列幅（リサイザで変えた値）は畳む前のまま戻る。開閉とパネルの選択は保存しない（毎回「マッピング」で開く）。
- 編集履歴はツール列の見出し行（パネル名の右）へ移す。全幅のバーはなくす。畳んだ間はボタンが見えないが、
  キー操作（`Cmd/Ctrl+Z` など）は効く。
- 「設定・共有」メニューは廃止する。3D とプロジェクトのパネルを開くことを、従来のメニュー項目と同じく
  3D 設定・プロジェクトの明示操作として扱い、そこで初めて PracticePanel（Three.js）を読み込む。
  マッピング・出力・確認のパネルだけを使う間は読み込まない。
- 会場の作成・調整（`/venue`、別タブ）への入口はアクティビティバーの下端、閉じる（×）の上に置く。
  3D パネルの中に置くと、そこを開いただけで 3D を読み込んでしまう。会場の入口は 3D を読み込まずに開ける、という
  0013 / 0015 の性質を保つため、パネルの外に出す。
- 右側のタブ（マッピング／出力レイアウト／3D プレビュー）とアクティビティバーは連動させない。
  ソースを見ながら数値を触るといった組み合わせを妨げないため。

## 影響

異なるパネルの項目を同時には見られない（例: テストパターンを切り替えながら出力一覧を見る、出力設定とマッピング設定を並べる）。
よく併用する一覧と選択中の詳細を同じパネルに置いて緩和した。ステージで出力やマッピングを選んでもパネルは自動で切り替えない。
保存形式・3D の読み込み条件・会場画面（`/venue`）は変えない。会場画面のツール列は従来の形のまま。
パネルの切替・畳み・畳んだ間の Undo・キーボード操作・狭い画面・3D の遅延読み込みはブラウザ回帰テストで確認する。
