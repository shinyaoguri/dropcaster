# 0020: 新しい版の Service Worker は全ウィンドウを閉じたときに有効にし、操作画面で通知する

## 状態

採用 — 2026-11-15。メンテナと合意した
([#164 の決定コメント](https://github.com/shinyaoguri/dropcaster/issues/164))。

## 文脈

SW は install で無条件に `skipWaiting()` し、viewer は `controllerchange` で自動的に再読み込みしていた。
上演中に新しい版が配信されると、操作画面が再読み込みされ、`pagehide` で出力ウィンドウが閉じる。閉じなくても、
captureStream の元の canvas が消えるので投影は止まる。ホスト版は main への push ごとにデプロイされ、
`stamp-sw-version.js` が版を変えるので、viewer を変える merge のたびに起きうる。

ほかにも次のことが起きていた (#164 の回帰テストで再現)。

- SW 未登録の初回訪問でも、`clients.claim()` による `controllerchange` でページが 1 度再読み込みされる。
- 自動の再読み込みに、保存待ちの離脱確認 (#168) が出る。キャンセルすると更新が適用されないまま残る。

## 決定

- install で `skipWaiting()` しない。新しい版はブラウザ標準のライフサイクルどおり、そのオリジンのタブ・
  ウィンドウがすべて閉じたときに有効になる。`activate` の `clients.claim()` (初回訪問からオフラインで使うため) は残す。
- 適用のメッセージは `DC_APPLY_UPDATE` とし、`SKIP_WAITING` は受けない。この変更より前の版のページは、
  新しい版が installed になると自動で `SKIP_WAITING` を送って再読み込みしていた。それに応じると、
  この変更を含む最初のデプロイで、開いている上演が再読み込みされ出力ウィンドウが閉じる。
- install でシェル HTML と、それが読み込む JS / CSS・そこから辿れるチャンク (遅延読み込みの画面を含む)・
  CSS の `url()` を事前キャッシュする (scope 内だけ)。新しい版の資産は、旧版のページが開いている間は誰も
  取りにいかない。揃えないと、閉じて新しい版が有効になった後にオフラインで開くと何も出ない。
  - シェル HTML とこれらの資産は必須。1 つでも取れない (200 でない・資産の代わりに HTML が返る)、または
    200 件を超えたら install を失敗させ、その install で作った shell を消す。新しい版は待機に入らず、旧版の
    まま動き、次の更新確認でやり直す。
  - manifest とアイコン (`<link rel="manifest|icon|apple-touch-icon">`) は任意。無くてもアプリは動くので、
    取れなくても install は続ける (アイコンを置いていないギャラリーで更新が止まらないように)。
- 版 (CACHE_VERSION) を持つのは shell だけにする。中身のバケット (local・op-meta・gist・op-cdn・runtime) は
  版の無い名前で、版をまたいで同じものを使う。activate で消すのは古い shell だけ。中身のバケットが版を
  持っていたころの名前 (`dropcaster-local-<版>` など) からは 1 回だけ中身を移して旧名を消す。runtime にある
  サブパス配信の `assets/` は shell から引くようにしたので移さない。
- viewer は自動で再読み込みしない。新しい版が待機しているあいだは、操作画面にだけ「新しい版があります」を
  控えめに出し、押したときだけ `DC_APPLY_UPDATE` を送って、制御が移ったら 1 度だけ再読み込みする。
  出力ウィンドウ (about:blank の別 document) には出さない。操作画面そのものを全画面にしているあいだも出さない。
- 遅延読み込みのチャンク (3D プレビュー・会場ページ) が取れないときは `vite:preloadError` を受け、
  自動で再読み込みせず「この画面を読み込めませんでした。新しい版が出ているか、接続が不安定な可能性があります」と
  案内する。Wi-Fi にはつながるが外に出られない会場もあるので、原因は断定しない。失敗の扱いは各画面に任せる。
  オフライン (`navigator.onLine === false`) と分かるときは、接続の確認を案内する。
  別のタブで新しい版が適用され、このページが旧版のまま新しい SW の制御下に入ったときは
  「新しい版が出ています。再読み込みしてください」と案内する。

## 退けた案

- **投影中だけ切り替えを保留する**: 出力も編集画面も開いていないときだけ即時に切り替える。全タブ・会場ページの
  状態を登録側が知る必要があり、判定漏れがそのまま再発になる。
- **即時に切り替え、再読み込みだけやめる**: activate で旧版のキャッシュが消え、開いたままの旧ページと SW の版がずれる。
- **activate で旧版の shell を新しい版へ写す (事前キャッシュの代わり)**: 実際のデプロイでは新しい版の HTML が
  別のハッシュの資産を参照し、それは旧版の shell に入っていないので、オフラインの起動を救えない。
  写すたびに使われない旧資産も溜まり続ける。
- **中身のバケットも版ごとに分け、activate で新しい版へ写してから消す**: 写すたびに中身が版をまたいで
  溜まり続けるうえ、版ごとに分けている意味 (デプロイで消せる) も無くなる。activate が全エントリを写し終える
  まで、最初のナビゲーションも待たされる。
- **事前キャッシュをベストエフォートにする**: install 中に回線が切れると、資産が欠けたまま待機に入り、
  閉じた時点で旧版の shell を消すので、オフラインで開くと何も出ない。

## 影響

- 開きっぱなしのタブ・インストール済み PWA は、閉じるか通知から適用するまで旧版で動く。修正版の到達が遅れる。
- 通知から適用すると再読み込みで出力ウィンドウは閉じる (ボタンのツールチップで伝える)。上演の合間に押す前提。
- 旧版のページで開く遅延チャンクは、その版の SW が install で事前キャッシュしているので、デプロイで消えても開ける。
  SW の無い環境 (`enablePwa: false`・secure context でない) で、デプロイ先にも残っていなければ、その画面は開けず
  案内が出る。デプロイ先が旧資産を残すか (Cloudflare の SPA fallback がサブリソースに効くか) は未確認。
- デプロイでは中身のバケットを消さない。中身は各戦略の再取得 (local・runtime の SWR、gist の NetworkFirst、
  op-meta の 24 時間) で新しくなる。op-cdn は CacheFirst なので、一度入った応答はブラウザが追い出すまで残る。
  消したいときは、利用者がブラウザでこのサイトのデータを削除する。
- `dropcaster dev` では、Vite のモジュールが runtime に残り続けていた。#180 で dev サーバは SW を登録しなくなり、
  残っていた登録も開いたときに外す。
- install の事前キャッシュは、遅延読み込みの画面の分 (現状で約 0.8 MB) も初回訪問で取りにいく。
- シェルから辿る資産は、バンドラが出す参照の形 (`./x.js`・`assets/x.css`) に頼る。形が変わって辿れなくなると
  オフラインの起動が壊れ、存在しない参照を拾うと install が失敗し続けて更新が届かない。どちらも #164 の
  update テスト (3 経路のビルド) が検出する。
