# 0011: メートル単位の部材編集と作品を含めない会場配布

## 状態

採用。#130 / #131。ADR 0010の保存形式を拡張する。

## 文脈

#124初期版はGLB読込に対応するが、利用者が実際の会場をアプリ内で作る方法がなかった。
利用者は壁・床・箱の実寸配置と、別の利用者が自分の作品で使うための会場配布を求めた。
映像・2D操作・実出力を既存のまま保ち、形状作成のためだけに外部モデラを必須にしない。

## 決定

- `VenueScene.kind: objects` と部材配列を追加。壁・床・箱は有限の正寸法を持つ直方体とし、
  id/name/kind/size/position/quaternion/colorを保存する。128個まで、各寸法0.001〜1000m。
  位置は中心、右手系Y-up。部材は物理メートルのため親の倍率・回転・移動・tintは恒等値に限定する。
- 部屋のひな形は内寸から生成し、壁厚15cmと床厚10cmは内寸の外側に置く。手前と天井は開放する。
  数値編集・複製・削除・直前変更への復帰を既存ツール欄で行う。
- ProjectをschemaVersion 2へ更新する。v1と旧MappingsState v2は既存値を保ってv2へ移行する。
  旧readerが未知のobjectsを落として異なる会場を表示しないよう、versionを明示的に分ける。
- 配布用の`dropcaster-venue` schemaVersion 1はname/venue/assetsのみを含む。
  Projectと別の状態管理は設けず、同じVenue型・parser・GLB検査を使う。作者の作品参照、show、screenは含めない。
  取り込みは全検証・モデル準備後にまとめて適用し、受信側のproject id/name/content/showとstreamを保持する。
  非同期GLB読込中に作品が進んだ場合も、その最新状態を保持する。
- 生成部材も既存ProjectionPreviewの投影・遮蔽・背景描画を使う。部材編集では観察カメラを動かさず、
  会場を新規作成したときだけ全体表示へ合わせる。変更時に前のgeometry/materialを解放する。
- 開始ボタンは個別作品の`top-right-button`、スライドショーの`control-btn`をそのまま共用する。
  アイコンは立方体、日英のtitle/aria-labelを付ける。

## 影響

外部モデルなしで簡単な会場を構築・配布し、受信側も部材を編集できる。既存GLBは引き続き全体transformで扱う。
自由形状のモデリング、スキャン、複数プロジェクタの同時寄与、クラウド配信は追加しない。
新形式の受信には更新済みのアプリが必要。旧データの読込互換は維持する。
検証は[記録](../verification/130-venue-authoring.md)、利用手順は[会場作成ガイド](../venue-authoring.md)へ残す。
