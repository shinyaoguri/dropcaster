# 0024: 映像は p5.js の作品側で作り、dropcaster は立体へのマッピングだけを担う

## 状態

採用（2026-11-16）。#248。面ごとに別の作品を読み込む #123 は、この判断により採らない。

## 文脈

一般的なプロジェクションマッピングツールや VJ ソフトは、動画・画像素材の読み込み、複数素材のレイヤー合成、
エフェクトの個別適用やブレンドまでを 1 つのアプリで扱う。dropcaster にも同じ機能を足す提案が出うるが、
その線引きはどこにも書かれておらず、提案のたびに方針を説明し直す必要があった。

dropcaster の入力は OpenProcessing・公開 Gist・ローカルの p5.js / html 作品で、作品の canvas を
`captureStream` で取り出して面へ配っている（[0001](0001-same-origin-sandboxless-iframe.md)・
[0002](0002-canvas-backing-store-decides-quality.md)）。作品はコードなので、素材の読み込みも合成も
エフェクトも作品の中で書ける。

## 決定

- **映像の中身はすべて p5.js（html モードを含む）の作品側で作る。** dropcaster は作品を取得・実行し、
  その出力を立体や面へマッピングして投影する部分だけを担う。
- **同時に読み込む作品は 1 つだけ。** 面ごとに違う映像を出したいときは、1 つの作品の canvas の中に
  面ごとの内容を描き分け、dropcaster はその canvas から各面へ写す範囲を切り出す。
- dropcaster が担うもの:
  - 作品の取得・実行・切り替え（OpenProcessing・Gist・ローカル、ギャラリー、キュー）
  - 1 つの作品の出力のどこを、どの面のどの形へ写すか（切り出し・quad・会場の立体・マスク・複数出力）
  - 出力機器と会場に合わせる補正（プロジェクタの位置合わせ、出力ごとの明るさ・色の補正 #199 のような機器差の吸収）
  - 作品が自分で公開したパラメータを外から操作する口（#122）。値をどう映像に反映するかは作品が決める
- dropcaster が担わないもの:
  - 動画・画像・音声などの素材ファイルを dropcaster 側で読み込んで投影すること
  - 複数の作品を同時に読み込み、面ごとに別の作品を割り当てること
  - 複数の作品・素材をレイヤーとして重ねる、ブレンドモードで混ぜる、クロスフェードで混ぜること
  - ぼかし・色調変換・フィードバック等のエフェクトを、作品の外から映像に掛けること
- 境界の判断:
  - マスクは面の形を切り抜く幾何の操作なので担う（黒で塗るだけで、映像を混ぜない）。
  - 面ごとに別の映像を出すのは、1 つの作品の描き分けと切り出しの組み合わせで実現する。
    面ごとに別の作品を読み込む案（#123 の A）は採らない。
  - 出力ごとの補正は、同じ映像を機器の差に関わらず同じに見せるためのもので、作品の見た目を演出として
    変えるためのものではない。演出としての色や明るさの変化は作品側で書く。
- 素材を混ぜたい・エフェクトを掛けたい要望には、p5.js の作品として書く方法（`loadImage` / `createVideo`・
  `blendMode`・シェーダ等）を案内し、dropcaster の機能としては足さない。作品側で書けない制約
  （素材の CORS など）があれば、作品を動かす側の問題として個別に扱う。

## 影響

- 素材ミックスやエフェクトの UI を持たないので、マッピング画面は面・出力・会場の操作に集中できる。
  作品の canvas を 1 本の stream として扱う前提（解像度・taint・共有）も崩れない。
- 既存ツールのように素材を並べて混ぜたい利用者には、p5.js のコードを書く手間が残る。dropcaster は
  クリエイティブコーディングの作品を投影するための道具であり、その手間は製品の前提として受け入れる。
- この範囲を広げる提案（素材の読み込み・合成・エフェクトの追加）は、この ADR を廃止または更新する判断として
  Issue で議論する。
